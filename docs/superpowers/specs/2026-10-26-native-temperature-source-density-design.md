# Temperature source density: bounded lossless successor design

2026-10-26. **Design only; no product implementation or live qualification performed.** Source inspected: clean runtime worktree `e5828bd4c5e4059032713f5d628fa097e0264d34`. Runtime evidence is the adjacent `overnight-20261026-runtime-diagnosis.md`; this pass made no DB/HTTP calls and ran no publication, scoring, fitting, or reproduction jobs.

## Decision and unavoidable contract amendment

Recommend one **shared, lossless, segmented original query** for the three thermal roles, with one stable acquisition and continuous selection across all segments. Preserve the old source readers and their exact limits. Introduce an explicit new source/binding/capture profile, selected only by a qualified successor runtime.

There is no solution satisfying both “retain every original row in the complete current day” and “the sum of those raw row bytes remains at most 8,388,608.” The live raw total already exceeds that number. Compression, dictionary encoding, and file partitioning cannot make the original raw-byte sum smaller. Thus this proposal requires this narrowly stated amendment:

> For the new shared-query profile only, replace the 8 MiB **whole logical query** limit with an 8 MiB **individual segment** limit and a hard **24,000,000-byte total shared query** limit. Count every decoded segment and the manifest toward that total; also cap total original raw UTF-8 bytes at 24,000,000. This changes the allowed size of one logical query. It does not change the historical v1/v2 contract or increase the existing 24,000,000-byte issue aggregate.

If preserving 8 MiB for the entire logical query is non-negotiable, publication must continue to refuse this history. Do not describe this successor as preserving that particular bound. No resource, deadline, row-count, receipt-validity, or model-qualification amendment is proposed.

## Alternatives considered

| Approach | Assessment |
|---|---|
| Compact/delta-encode one whole-day container | Lossless storage can shrink, but decoded original bytes still exceed the old raw bound. A new expanded-work bound is still necessary. Adds codec complexity without addressing three repeated role acquisitions. |
| Partition independent v1 queries for each role | Retains familiar files but repeats raw evidence three times, threatens the 24 MB aggregate, and resetting the selector at each boundary can change results. A validity overlap alone does not prove equivalence. |
| Shared original query, bounded storage segments, continuous multi-role replay | Recommended. Stores every original observation once, keeps explicit role policies, reduces acquisition and envelope decoding, and retains the existing total issue budget. Requires the explicit whole-query amendment above and new qualification. |

The existing `household_native_score_queries.py` endpoint-window primitive is not a substitute: applying endpoint-only windows to this origin day would omit actual intervening observations. Leave that separate score-query contract unchanged.

## New source and replay contract

1. **Acquire once.** Validate and freeze all three role contexts before connecting: role, stream, exact approved `TemperaturePolicy`, hardware epoch, common targets, assessed_at, and history_start. The latter remains exactly first target minus 120 seconds. Reuse the unchanged `_fetch_rows` once with the caller's remaining deadline. Keep its sole Item mapping, explicit carry, NULL/oversized barriers, row ordering, read-only REPEATABLE READ, 2 s statement/1 s lock/5 s idle limits, and rollback-on-close. No per-role or per-segment DB query. A single snapshot is the new original; do not claim equality to independently acquired old snapshots that may have seen different late persistence writes.
2. **Retain every supplied observation.** Preserve original stored instants and complete raw text bytes returned by the existing bounded SQL, including all four envelope roles, invalid/malformed rows, equal duplicates, collector transitions, and NULL barriers. An oversized SQL value remains the existing NULL barrier; this format does not claim to retain bytes the SQL contract did not return. Never normalize embedded JSON, sample, filter, or deduplicate observations.
3. **Segment storage, not selection.** Use an explicit new closed manifest and segment schema, proposed `earthship-native-temperature-shared-query/v1` and `earthship-native-temperature-query-segment/v1`. Manifest contains frozen context, ordered segment descriptors, global row/raw/decoded totals, original carry count, transcript digest, and `release_authority=false`. A descriptor binds ordinal, row offset/count, first/last stored instant, raw and canonical byte counts, decoded digest, compressed digest, and an exact content-addressed basename. Segments bind the context digest and ordinal and contain consecutive original `[stored_at, raw_or_null]` rows. No extra “carry” at an internal segment boundary.
4. **Hard bounds.** At most three segments, each original raw total and canonical decoded document <=8 MiB; each gzip file <=8 MiB+4,096. Manifest <=65,536 bytes. Manifest plus all decoded segments <=24,000,000 bytes, total original raw bytes <=24,000,000, and total stored bytes <=24,000,000. Across the whole capture: <=10,000 rows including at most one original pre-window carry, <=289 increasing targets spanning <=24 elapsed hours, <=8,192 raw UTF-8 bytes/row, exactly three thermal contexts. Reject before publishing a manifest if any bound fails. Do not recursively nest manifests or admit extra segments. These remain finite acceptance bounds; arbitrary future density is not promised.
5. **Unambiguous identity.** Retain ordinary canonical JSON and deterministic gzip level 1/mtime 0. Hash both stored and decoded bytes. Hash the complete ordered observation transcript using a versioned domain separator, frozen context digest, and length-prefixed canonical row bytes. Verify counts/offsets/totals against actual bytes, not manifest claims. Bind the manifest digest and all three contexts into a new origin-binding schema (`earthship-installed-shade-native-origin-binding/v3`). The three existing input role references may point to the same manifest, but the new binding must require that equality and exact role identities. Neither a missing role nor a scalar-only proof can substitute.
6. **Continuous, shared replay.** Decode each envelope once, calculate its original raw snapshot SHA256 once, and apply the existing v2 validation and barrier transitions separately to the three roles. Keep `selected`, `barrier_at`, and collector epoch per role, plus global previous timestamp/raw ordering state, across segments. Preserve exact receivedAt/storedAt/validUntil, sensorEpoch, receiptVersion, snapshotSha256, numbers, and None results. Reject conflicting duplicates anywhere, including across boundaries, before returning any grid. Segments contain no trusted cached selector state. Read every original segment on independent replay.

The incremental selector should be a new module, with the old pure selector as its independent differential oracle; do not refactor or change the pinned legacy reader. Reuse its strict JSON/timestamp/policy primitives where possible. A malformed selected-role record must not accidentally invalidate an otherwise valid different role, beyond the existing shared-envelope checks.

**Boundary hazard:** a rejected copied receipt advances `barrier_at` to its storage time. A chain of later receipts behind each moving barrier can remain invalid indefinitely. Starting a new selector with one carry and even 120 seconds of overlap can accept that chain. Therefore “overlap is long enough” is not an acceptable proof; replay starts once at the original day carry and never resets.

Use the existing private regular-file/ownership/no-symlink/atomic-create primitives. Publish chunks first and the manifest last, with the existing guard after temporary writes and before links. A failed attempt must not expose a complete manifest. Fresh replay and final source verification must enumerate the manifest **and every child segment**; manifest-only fingerprints are insufficient. Keep invocation-local reuse tied to the same frozen context and source inventory; no process-wide or cross-issue freshness cache.

## Work and resource bounds

This is one acquisition instead of three, at most 10,000 envelope decodes/hashes and 30,000 role validations per full replay. Decoded original-source work is explicitly bounded by the unchanged 24 MB issue aggregate, without decoding that full aggregate independently for each role. Build canonical segments incrementally; do not repeatedly serialize an ever-growing list per row. Replay one segment at a time, retaining only three selector states and <=867 selected points.

Do not claim constant 8 MiB process memory: unchanged `_fetch_rows` uses fetchall. Its SQL overflow sentinel permits 10,001 window rows plus one carry before rejecting a result above 10,000, so its pre-validation maximum row payload is 10,002×8,192 = 81,936,384 bytes, plus driver/Python overhead. That pre-existing acquisition maximum is not increased and occurs once instead of up to three times. Replay also has compressed/decoded buffers and Python objects. Measure actual RSS, CPU time, wall time, source read counts, and cgroup events under the real launcher; no invented pass threshold or arithmetic-only qualification.

All existing publication/acquisition clocks remain (85-second enclosing budget and 90-second publication window), as do 50-second native score acquisition, 120-second full scoring, 240-second activation, 150-second safe activation window, global 6,144 MiB/8 CPU/256 tasks/no swap, per-job <=128 tasks, actual unit memory limits, priority, headroom, pressure, locking, and cleanup gates. Existing 64 MB score-query, source inventory, and report bounds remain; new child files count toward every relevant existing inventory. Check deadlines inside serialization/decoding loops as well as before/after IO.

## Required gates before deployment or a completion claim

1. **RED before code:** prove old source rejection for a finite >8 MiB raw day, and separate canonical-only and three-role aggregate crossings. Preserve the supplied Oct 24/25 originals and read them with their exact old readers. Do not fabricate extra rows into those originals. Use labeled synthetic dense fixtures for thresholds, with the unchanged pure v2 reader over the full row list as the selection oracle.
2. **Independent equality:** compare every field of all three grids for old retained inputs, full 10,000-row bounded fixtures, and adversarial partitions. Include boundary NULL/malformed/oversized barriers, moving-barrier chains, invalid/wrong/missing hardware epoch, collector reset/copied restore, equal/conflicting timestamps, backwards receipts, exact expiry, target/carry boundaries, UTF-8 and microsecond clocks. Verify concatenated retained rows equal original rows byte-for-byte and in count/order. A test that checks only temperature numbers is insufficient.
3. **Refusal and custody:** +1 byte/row/segment/target limits, forged totals, reordered/missing/extra/spliced segments, truncated/bomb/concatenated gzip data, duplicate JSON keys, wrong policies/roles/clocks, wrong content addresses, path aliases, file replacement/deletion during and after replay, source changes during final publication guard, and canceled deadlines. Old readers must reject the new format. Legacy packet/capture replay stays exact under the frozen release.
4. **Full offline runtime qualification:** cold focused/regression tests and complete actual source-bound candidate/admission/forecast/cycle/score/report replay under original launchers and caps, including retained fit equality, complete child-source read inventory, rollback, zero resource-event increments, and original terminal cleanup. Exercise real full 1/6/12/24-hour score/report paths; do not replace them with mocked numerical replay or just the new codec test. The 120-second score and activation safety windows are binding failure gates.
5. **Read-only current capture gate:** after source review and parent resource allocation, one bounded current full-day capture through the new single-snapshot port, into a fresh private destination, with per-segment/global counts and bytes, acquisition clocks, complete replay, and measured resource telemetry. No publish/fit/activation as a diagnostic shortcut. Current four-stream freshness qualification remains separate and must not be invalidated by poll/TTL changes.
6. **Guarded successor deployment:** clean committed source, exact reviewed archive, new external runtime/candidate/receipt/dispatch pins, unchanged fit originals and base source hashes, existing resource admission and safe handoff, owner/timer restoration and rollback records. The old immutable R5 tree remains untouched.
7. **Natural operation:** observe a scheduled fresh thermal publication with actual persisted receipt/readback and complete retained new-source replay, then the dependent household cycle and analytics product refresh. Later verify mature scoring against that actual new capture and normal publication as the full trailing window remains dense. Report source/test/install/natural-cycle/mature-score status separately. No actuator authority or model graduation follows from this repair.
