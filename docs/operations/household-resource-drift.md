# Household resource vectors and drift

The pure `household.resources` boundary rederives an original sealed shadow plan and reports each candidate's declared effects separately. Battery energy, SoC percentage points, temperature, water and equipment wear retain their units. Comfort degree hours and curtailed energy remain unavailable because the existing intent contract provides no such effect estimate. Positive normalization scales are explicit retained preferences; they are neither measured response coefficients nor safety thresholds.

`seal_resources` retains the unchanged original plan, scales, analysis clock, executing analysis manifest and up to 16 explicit alternative candidate orders. Selected-order analysis and alternatives report every prefix, signed final drift, minimum/maximum prefix and gross movement. A loss followed by an equal gain therefore retains the adverse intermediate excursion. Unknown contributions make net changes, extrema and gross totals unknown; known subtotals and unknown candidate identities remain visible. The empty optional schedule has zero additional declared effect, while the actual household baseline remains unqualified.

Alternative orders can contain rejected or unknown candidates. The original decision and hard-check results accompany each candidate; diagnostic order analysis grants no feasibility, causal, graduation or actuator qualification. Prefixes cover endpoint effects in the given action order. They cannot establish excursions within an action, parallel-action timing or physical bounds without qualified response trajectories. No combined unexplained resource scalar is produced, and the existing planner selection is unchanged.

`household_resources.py --receipt /private/resource-analysis.json` requires an owned mode 0600 regular file. It verifies the full original planner closure, actual current analysis dependencies, clocks, original bytes and runtime again before stdout. Additional observational modules may be installed without falsely inserting them into an earlier original plan. Replay reads no live sources and exposes no action, notification, database write or service operation.

Validation: 21 pure and 7 private CLI contracts passed under CPU 20%, memory 256 MiB, swap 0, tasks 24, nice 15, idle I/O and one numerical thread. The 595 affected household, forecast and atomic SoC regressions passed in 151.61 seconds under the same limits. An actual retained original thermal-only plan replayed identically through pure analysis and the private CLI; that plan contained zero optional candidates. This verifies actual original-context replay, not measured action effects or nonempty production scheduling benefit. Private receipts remain outside Git.
