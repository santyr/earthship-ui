# Conditional battery forecast outcomes

PR #3's chronological evaluation now has a battery endpoint producer and a curated Earthship comparison panel. This adds measurement of the existing constant-net-DC-power baseline against holding the original battery SoC constant. It does not qualify future PV/load forcing, usable capacity, action response, graduation, or actuator authority.

The producer uses original v6 household plan receipts. Each compact outcome binds the original semantic receipt hash and canonical document hash; the complete plan stays in its immutable evidence archive. Offline verification uses `household_battery_outcomes.py --receipt SCORE --plan ORIGINAL`, rederives the original plan with the executing source closure, then recomputes the endpoint errors. It reads files only.

One original forecast is sampled per UTC issue hour. Supported endpoint horizons are 1, 6, 12 and 24 hours, with five minutes allowed before collection. The fixed local read-only database transaction obtains at most two original BMS rows within the 120 seconds ending at the target. A latest NULL, malformed, unavailable, expired or changed-epoch receipt never falls back to an older valid SoC. Tied or unordered persistence clocks refuse acquisition. Acquisition failures receive a bounded 30-minute per-origin retry delay, allowing other mature origins to proceed on normal score slots. No active retry loop runs.

Each successful endpoint packet is immutable and reused for later horizons. Model source, declared bank epoch, nominal capacity and BMS source epoch identify the cohort. The active report includes at most seven days of hourly origins, deduplicates each origin/horizon, and shows sample counts, attempted endpoints, distinct local origin dates, mean absolute error and bias for both baselines. Repeated intraday origins are correlated; the distinct-day count is descriptive, not an independence claim. Unknown endpoints add no numerical pair. Aggregate validation rechecks retained endpoint evidence and arithmetic; it is explicitly producer-pair aggregation, not repeated full-plan qualification or model graduation.

The original rollout ran an optional battery step after thermal scoring. The scheduling correction below gives battery work its own opportunity in the existing score service, under the same shared lock. It allows at most 20 seconds of producer work inside a 45-second total invocation, including setup and dispatch, and reserves 10 seconds for final verification. Battery slots bypass thermal model selection and scoring. Thermal clocks and their 120-second budget remain unchanged. The shared resource pool, trained thermal model and equipment owners are unchanged.

Private state lives under `~/.local/state/household-intel/battery-outcomes/`. A fixed curated cache, `battery-performance.json`, is available through GET `/api/household-battery-performance`. The HTTP handler performs bounded private-file validation only; it cannot select arbitrary files, query the database, execute models or renew original clocks. The existing Earthship household panel displays both errors in SoC percentage points, empty horizons as collecting, original report age/staleness, the last measured endpoint and the next pending assessment.

Validation: all 1,374 affected household/native-scoring tests passed in 231.78 seconds after the single review correction pass; 59 parser, transport and UI render tests pass. The immutable review of `9a20860` identified three Important retention defects: incompatible historical candidates could starve compatible plans, a later failed query could discard an earlier successful packet, and expired references were checked against removed stages before pruning. All three had failing regressions and were corrected once, with no rereview. Successful partial acquisitions now seal while missing mature targets remain explicitly pending and add no terminal attempt or numerical error. The original daily-source record, receipt, state-hash and authority checks remain intact after removing one obsolete schema-only assertion.

Production rollout and natural endpoint evidence are recorded below. The canonical program tracker remains the full-scope record.
