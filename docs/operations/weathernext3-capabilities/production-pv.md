# Native component PV replacement - prepared, not installed

The replacement fits a new bounded scalar electrical gain to the native
SSRD/FDIR component baseline. The gain applies only to native-component
segments. Total-only fallback segments retain their raw potential. The
incumbent directional coefficients are not transferred to this baseline.

All 768 retained matched rows were replayed through the current complete
20-file baseline closure. Both native and total-only powers matched their
original values exactly. The fixed support rule selected 737 historical
targets on 29 local dates; the 31 rows with recorded ingestion availability
remain a separate population. These dates are not a claim of independent
samples. Original source, target, geometry and label-arrival clocks remain
unchanged. The fit is an experimental controller-input proxy adjustment;
it neither establishes unrestricted MPPT output nor physical calibration.

The actual final fit completed on 2026-10-23 at 02:27:06.832328 UTC. Its
coefficient is 0.6487249745358313 and original validity ends on 2026-11-06
at the same UTC time. A no-op fit preserves the original bytes and clocks.
The final scope required a genuine refit after tests caught a prototype
that also adjusted total-only fallbacks. Both generations retain their
literal source/policy packages; the prototype remains superseded.

The explicit component profile pins the model file, physical configuration,
measured-power cohort, numerical environment, source closure and deployment
authorization. Expiry at a new forecast origin uses a named raw-component
fallback. Expiry or a changed owner during a used compilation refuses the
commit. Loading or scoring an old original never renews the model.

## Daily publication and evaluation

The new optional daily worker path produces a v4 view and a private v2
original receipt. Preparation is the default. Publication requires the
explicit component profile/hash and --component-publish. Legacy CLI
defaults and old receipt meanings remain unchanged. Publication uses
atomic cache replacement and exact byte readback, then retains a confirmed
emission with the real publication time. A failed retention after cache
success reports PUBLISHED, exits unsuccessfully and does not enter scoring.
An uncertain cache write reports PUBLICATION_UNCERTAIN.

The private receipt is bounded at 8 MiB, matching the monitor's existing
reader. A real ten-day preview used 2,587,530 bytes and a 6,294-byte view;
all ten days were available in 9.370 seconds at 112,044 KiB peak RSS.
It made five local OpenHAB GETs, no cloud requests, no model fits, no Item
writes, no public cache write and no selector changes. Its preserved proof
is 4a8b7888489fe17ba0ef03ac5e6ebf63ee598290eea92efaa8924aa682b9ddcc.
This proves preparation, not an issued forecast or deployed model.

Before retaining a new receipt, the new path reserves the receipt and
emission together against a 2 GiB/10,000-entry daily namespace limit,
including old originals and geometry, with 32 MiB disk headroom. It
withholds a new cache on capacity failure and does not delete originals.
No shared CPU, RAM, task or acquisition limits change. Track actual archive
growth and arrange verified export before capacity exhaustion.

The existing hourly monitor accepts only confirmed original component
emissions published before the measured hour. It validates their literal
view, model, policy, procedure, physical and measured-power cohort,
integration bins and native-only adjustment. It compares the original
five-minute constituent powers used in the published daily totals with
qualified low-SoC charging controller input. This is not observed daily
energy accuracy. Unconfirmed preparation never enters the monitor.

Scores retain model, fitting procedure, baseline, measurement and grid
identities. The v2 accuracy report separates them from legacy populations
and counts local target dates without asserting independence. The existing
monitor and seven-day public report own this work; no extra scoring actor,
shadow producer, collection or fitting is introduced.
