# Household model boundaries

The daily energy calculation now delegates to `household.energy_model.daily_energy_projection`. The existing worker still selects qualified atomic SoC and completed-night evidence. The extraction preserves its configured bank capacity, overnight-drop fallback, cloud penalty, rounding, dusk calculation and curtailment proxy. Numerical estimates do not establish a physical bank epoch or qualified action effect.

The parity fixture `openhab/scripts/household/fixtures/energy-production-v1.json` retains 72 input/output cases generated from the exact production statements at revision `d0aafa39b31671a7850227d3e9d5f50493158e86`, with the original source SHA256. Cases include unavailable SoC, battery bounds, low/high solar resource, overnight fallback and cloud thresholds. The tests compare extracted outputs against those frozen originals.

`household.thermal_model.prepare_projection` verifies a retained provisional origin using the mature complete source validator. This includes original candidate/training bytes, native query packets, forecast receipts and action knowledge at the original issue. It freezes numerical forcings, coefficients, source-linked observations and a snapshot. It records the original artifact runtime separately from the actual executing thermal closure and household wrapper sources, preserving the existing 72-file thermal limit. Source bindings are rechecked across preparation; group-writable runtime sources are refused.

`project` consumes that immutable context and performs no file, database or OpenHAB reads. It reuses the existing installed-shade dynamics and must reproduce the original production trajectory exactly before preparation succeeds. Measured north-wall temperature stays distinct from the existing latent mass observer state. The snapshot describes readiness at the original issue, not freshness today. Serialized prepared bytes are a mathematical cache; verify the retained originals through preparation before treating a reloaded cache as source evidence.

The projection retains low confidence, unavailable prediction intervals, no advice, no graduation and no automatic actuation. It explicitly withholds action-effect qualification. A successful 24-hour original production replay is recorded in the private implementation ledger. It proves parity, not causal benefits from ventilation or shade changes.

The standalone worker dependency is now a three-file set: `forecast_intel.py`, `household/__init__.py` and `household/energy_model.py`. Install that set together before deploying the updated worker; copying only the worker is incomplete. No live files, timers, model coefficients or owner rules are changed by this source PR. Existing recovery deployment manifests remain tied to their old generations; recovery work stays deferred.

Run local tests and replay probes through the shared job launcher, which accounts for combined development and production commitments; see [the shared resource policy](2026-10-14-shared-job-resources.md). Expanded energy/bank/power fields, weather/action context representation, model-backed intents, constraints, arbitration, full household-plan replay, outcome qualification and observability remain part of the full PR #3 goal.

The new `household.energy_persistence` model is a conditional baseline for 6-, 12- and 24-hour evaluation. It keeps the original atomic SoC and battery DC power, declared nominal bank capacity, and original fixed metric-source sign/unit/scale declaration. Positive power means charging. Hourly points retain nominal SoC-equivalent energy and mathematical excursions above or below capacity. The model assumes the current net DC power persists; it supplies no hourly PV forecast, future load response, calibrated usable energy, efficiency estimate or physical protection threshold. Its minimum never becomes a reserve-permission fact.

Pipeline/v6 records the original metric source and rederives the separate projection. The original daily output and all older receipt shapes remain unchanged. Missing, expired or skewed telemetry, unsupported semantics, missing capacity, or a bank window ending within the horizon make the baseline unavailable. Its confidence, future forcing and physical calibration remain unqualified. Fixed optional acquisition is part of cycle-sources/v5; raw metric configuration stays private. Public comparison, mature energy endpoint outcomes and qualified rolling forecasts remain subsequent requirements. Deployment evidence follows after normal-cycle verification.
