# Expanded original household power snapshot

`household.power_capture` composes the original household collector with fixed atomic power receipts. One 15-second deadline covers the base and added source reads. Queries use a dedicated read-only REPEATABLE READ transaction, the unique fixed Item mapping, at most two latest bounded rows, a two-second statement deadline and a one-second lock deadline. A newest NULL or malformed original remains a barrier. No historical numeric value substitutes for a missing receipt.

The compiler in `household.power_snapshot` reruns the original v1 compiler at the final shared clock. It preserves the original source timestamps and uses the companion's strict `parse_power_evidence` and `parse_ac_evidence` validators. Battery DC power, PV input/output power and inverter AC output preserve watts, field-specific expiry, exact original digest and software producer epoch. The inverter field is output observed at that inverter, not total household load. A producer restart does not establish a new physical bank identity.

The immutable `earthship-household-snapshot/v2` carries those facts alongside the existing SoC, PV day counter and temperatures. Required energy, thermal, weather and authority/status fields without qualified adapters remain explicitly unavailable. Capability completeness uses declared age/skew limits; unknown bank identity, usable energy, household load, trajectories and owner availability cannot become qualified through schema construction. Water inventory remains unknown.

`compile_power_inputs` seals the original bundle, ownership/capability documents, code revision, full runtime manifest and complete snapshot. `replay_power_snapshot` rederives all results without file, database or live API reads and rejects changed originals, runtime or resealed derived values. Existing v1 source, snapshot and planner files are unchanged. The new v2 snapshot still requires explicit model/planner integration; it grants no request or actuator authority.

The companion pin advances from d24771b to published 24d2e898 because the previous hosted revision lacks the existing AC parser. The selected parser bytes match the live companion checkout. The small intervening existing-reader changes add captured-at barriers and preserve the original power interval defaults; both hosted workflow pins move together. This does not install or change the live companion.

An actual read-only capture qualified nine original roles under the local CPU 20%, memory 256 MiB, swap 0, tasks 24, nice 15, idle-I/O and single-thread limits. Full energy completeness remained false. Original source and independent current owner-epoch receipts stay in approved private staging, with exact digest/readback and offline replay. A second actual capture from committed source 0512be3 retained all nine roles at 19:49:42 UTC and replayed identically; configuration/runtime/source reads were rechecked. Independent review and hosted verification remain finish gates; full Phase 2/PR #3 remain incomplete.

Validation: 40 focused snapshot/capture contracts and 635 affected household, forecast and atomic SoC regressions passed in 146.91 seconds under the serial local caps. No recovery suite was selected.
