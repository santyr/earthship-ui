# Original-source model snapshot and replay

`household.model_snapshot.bind_model_snapshot` creates the explicit immutable snapshot/v3 from a sealed original power receipt and an optional prepared original thermal projection. The original power snapshot/v2 and receipt identity remain retained. A present thermal context uses its actual original issue clock and exact native air, measured mass and outdoor rows; later power sources are refused, and previously available power facts are reassessed at that clock. Snapshot creation follows the thermal publication's actual availability. The measured mass row remains distinct from the model's latent observer mass.

The thermal artifact identity and low confidence are retained provisional metadata with `retained_model_context` quality. They do not qualify a physical action reference, causal effect or release. Missing model context remains explicit. Binding and replay use immutable packets; the strong original thermal preparation still occurs separately at the collection boundary.

Pipeline receipt/v2 and shadow-plan receipt/v2 retain deduplicated original source receipts keyed by snapshot identity. Replays restore the model snapshot type for both the root and each candidate's original validation context, rederive sources and all model/candidate/plan outputs, and compare the complete sealed result. Original producer hashes must match the executing planner. Operational CLIs additionally require the complete producer closure, including the existing AC/power parsers and interval module. A resealed partial manifest cannot substitute for the original producer dependencies. Receipts remain bounded at one MiB for the pipeline and 512 KiB for plans; snapshot content remains bounded at 256 KiB.

The v1 branch preserves its receipt schema and input shape. Energy mathematics, thermal trajectories, intent parameters, deterministic constraint math and the disabled translator remain unchanged. Proposals still carry unknown action effects and unavailable action confidence; owner coordination remains unknown unless separately supplied and qualified. No action execution is introduced.

This stage supports a shared expanded source/model identity. It does not finish physical bank/usable energy, total household load, forecast/weather/authority sources, rolling energy trajectories, live owner contracts, causal outcomes, operator UI or release qualification. The full PR #3 objective remains active.

Validation: seven snapshot boundary tests and sixteen expanded pipeline/intent/CLI tests are included in the complete affected run: 656 passed in 192.09 seconds under CPU20%, memory256 MiB, swap0, tasks24, nice15, idle I/O and single numerical-thread limits. Hosted broad checks, independent review and actual current-runtime source/model proof remain pending.
